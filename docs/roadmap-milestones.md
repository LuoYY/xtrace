## 2. M1 的内容与门槛（最近一档，展开）

- S0 反例入库（旧实现必红、独立目录、不覆写历史证据）→ S1 dump 所有权与受控根（删 TimedWait 模式、堆上请求状态、epoch 键、执行前校验）→ S2 配置/计账闭合（所属线程原子发布、每激活预算、model-2 等式、coverage 轴、旧等式删除）→ S3 编码器统一有界 writer（accessor 字节、RAB 逻辑长度、double-hole、GC 内部安全）→ S4 五元命名空间 + per-read 证据 + T7 等级分离 → S5 逐值真值对照 + 零打印分项基准 → S6 最终验收包。
- **授权门槛**：M1 的 cookie 链证明以本地 echo oracle + 语料复跑为准；**活站采集需用户显式授权**，未授权前 M1 不含活站断言。
- 主要风险：RR2（V8 生命周期所有权）与 RR4（编码器/GC）是内存安全类返工，历史最耗时——若 S1/S3 出现二轮返工，M1 窗口 +3–5 日。

## 3. M2 的前置决策（进入前必须冻结，避免块内停顿）

1. 证据索引存储形态（SQLite/LedgerBackend 同库或分库 vs 文件派生）——草稿 §11.2 已要求 P6 启动前冻结。
2. Broker 的授权粒度与 UI 审批交互形态（Electron 主/渲染进程隔离下的确认流）。
3. Agent 首批输入切片策略（限额证据切片 + 本地索引，不整 trace 入上下文）。
4. Node Host 与 ChromiumX 的进程所有权/重连模型（pipe 断开即浏览器退出的现实，见 P3 终审记录）。

## 4. 贯穿性门槛（每档都适用）

- 补丁栈强制同步（`verify_patches.py` + 逐文件比对）；基线固定 151.0.7917.0 不变。
- 全门禁：python/launcher/GUI + 契约 + 矩阵 off/observer + 故障 + 反例门 + **全部 C++ 测试目标（重建后）** + bindings。
- 证据纪律：反例先红后绿；绿灯不替代路径验证；"observed/derived/hypothesis" 分级不得越级。
- 每档结束由架构师终审；accepted-* 状态只能由架构师标记。

## 5. 明确不在路线内的项

- 全量 WebIDL 覆盖（永远不做，见 P5 讨论）；全 JIT 层逐指令追踪；通用自动还原任意 VMP 算法的承诺。
- 未经授权的第三方目标采集；断电持久化承诺。

## 6. 升级与变更规则

- 里程碑窗口偏移 >5 个工作日须回报原因（区分实现返工/审查发现/外部依赖）。
- 范围变更（新增/删减里程碑内容）走裁决流程，不得以勾选或注释替换。
- 每档的实际耗时回填本表（§7 速度基线随之更新）。

## 7. 速度基线（估计依据，2026-09-19 → 09-25 实测）

| 阶段 | 执行块 | review+整改 | 备注 |
