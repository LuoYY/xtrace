## 2. M1 的内容与门槛（最近一档，展开）

- S0 反例入库（旧实现必红、独立目录、不覆写历史证据）→ S1 dump 所有权与受控根（删 TimedWait 模式、堆上请求状态、epoch 键、执行前校验）→ S2 配置/计账闭合（所属线程原子发布、每激活预算、model-2 等式、coverage 轴、旧等式删除）→ S3 编码器统一有界 writer（accessor 字节、RAB 逻辑长度、double-hole、GC 内部安全）→ S4 五元命名空间 + per-read 证据 + T7 等级分离 → S5 逐值真值对照 + 零打印分项基准 → S6 最终验收包。
- **授权门槛**：M1 的 cookie 链证明以本地 echo oracle + 语料复跑为准；**活站采集需用户显式授权**，未授权前 M1 不含活站断言。
- 主要风险：RR2（V8 生命周期所有权）与 RR4（编码器/GC）是内存安全类返工，历史最耗时——若 S1/S3 出现二轮返工，M1 窗口 +3–5 日。

## 3. M2 的前置决策（**已冻结 2026-09-26**，见 [P6 交接 §5](chromium-p6-agent-loop-handoff.md)）

1. 证据索引：Node Host 内 SQLite、独立 index.db、派生可重建；事件级查询直读 NDJSON。
2. Broker 三档授权（只读会话级 / 有状态逐次确认+审计 / 宿主执行默认拒绝白名单）；Agent/UI/MCP 同径。
3. Agent 输入切片三形（manifest 摘要 / top-K 有界证据切片 / 索引查询），原始 trace 永不入上下文。
4. 进程所有权：Host 拥有浏览器；P6 不做重连，重启后"只读收养"或"终止孤儿"二选一。

## 4. 贯穿性门槛（每档都适用）

- 补丁栈强制同步（`verify_patches.py` + 逐文件比对）；基线固定 151.0.7917.0 不变。
- 全门禁：python/launcher/GUI + 契约 + 矩阵 off/observer + 故障 + 反例门 + **全部 C++ 测试目标（重建后）** + bindings。
- 证据纪律：反例先红后绿；绿灯不替代路径验证；"observed/derived/hypothesis" 分级不得越级。
- 每档结束由架构师终审；accepted-* 状态只能由架构师标记。

## 5. 明确不在路线内的项

- 全量 WebIDL 覆盖（永远不做，见 P5 讨论）；全 JIT 层逐指令追踪；通用自动还原任意 VMP 算法的承诺。
- 未经授权的第三方目标采集；断电持久化承诺。

规律（2026-09-26 修正）：执行块 1–2 日/阶段这条仍然成立，**但原来的"M2 需 3–4 周"估计错了一个数量级**——真正吃掉日历时间的不是执行，而是"审查发现 → 整改 → 复审"的轮次，以及外部依赖等待。因此：

- **返工占比 40–60% 的规律保留**，且对产品面同样成立：P6 的 6 项阻塞全部是 review 抓出的，工程师自测全绿。
- **缺陷类发生迁移**：引擎面（P2–P5.5）是内存安全/生命周期/计账等式；产品面（P6）是**接线缺失**（能力协商、env profile、孤儿处置、证据跳转都有代码但无消费者）、**夹具过小**（4 事件夹具使前缀窗口类缺陷结构上不可见）、**测试钩子住进产品路径**（工作区选择、deadline、夹具注入）、**审计形态正确而语义为空**（代码自批写下 `confirmed`）。
- **对策（P7 起写进工单验收锚点，不靠事后 review 兜）**：① 每个"等价/优先/覆盖/审计"类断言必须配**负控**（故意破坏→必须红）；② 至少一条门禁用**真实 capture**（≥2 万事件、非约定命名）；③ 组合根唯一化，源码形态核对（调用点 grep）入门禁；④ 产品路径禁止 harness 钩子，钩子只能是加速器且须标注。
- **第二条教训（R2，2026-09-27）：整改轮本身会引入退步。** P6-R1 为修 B5 而削薄 GUI 服务层，顺手删掉了已交付的计账诚实披露（丢弃计数/未确认 producer），并**削弱了 S3 断言**把它盖住；同时删掉五个测试文件而未恢复其覆盖（env 生命周期、loop 取消与熔断、索引重建等式、A-13 注册、不可用工具执行期拒绝、真机 pair），还在执行记录里申报了两项未做的修复（m1/m5）。对策：整改工单必须附**"不得削弱的既有断言清单"**，且整改 commit 的**删除测试行**须逐条给出替代位置；复审把"记录逐条 vs 实测（diffstat + grep）"列为固定动作。
- 窗口估算模型改为：**窗口 = 执行块（0.5–2 日）+ 整改（1–3 日）+ 终审（0.5–1 日）+ 外部依赖等待（frx 源码移交、活站授权，不可压缩）**。§1 各档日期按此重估（见 §8）。
